# Компактная выдача S06

`queryLogs` принимает необязательный массив `fields`: `line`, `structuredMetadata`,
`normalized`. По умолчанию — `["line"]`; `[]` оставляет время и ссылку на метки.
Неизвестные имена, null внутри массива и повторы — `INVALID_ARGUMENT` до HTTP-запроса.
Проекция не меняет LogQL. `normalized` — строковые JSON/ECS-кандидаты из
[нормализатора discovery](discovery.md), с исходными origin/path; конфликтующие пути
сохраняются. Это не выбор произвольного JSON Pointer из строки. Ошибки и лимиты разбора
указаны в `events[].limitations`. Ненайденные значения не угадываются.

```json
{"connection":"local","query":"{job=\"example\"} |= \"error\"","start":"now-15m","end":"now","fields":["normalized","structuredMetadata"]}
```

`streams` — словарь пар `streamId`/`resultLabels`; событие содержит `timestampNanos`,
`streamId`, выбранные поля, `truncatedFields` и `limitations`. Равные наборы меток
разделяют элемент словаря, но события не объединяются. Это словарь меток результата,
не доказательство исходного stream scope. Идентификаторы `s0`, `s1` локальны одному
ответу, не подходят для последующих вызовов. Неиспользуемые элементы словаря удаляются.
`resultStreams` по-прежнему считает потоки ответа Loki до локального ограничения,
а не элементы словаря. В корневом `fields` перечислена применённая проекция.

Длинные `line` и нормализованные значения сохраняют начало и конец: первоначальный
предел — 2048 Unicode code points плюс маркер `…[truncated]…`. Началу отводится 3/4,
концу — 1/4. Это сохраняет часть заголовка исключения и последних frames, но не
гарантирует сохранение всей цепочки причин. Surrogate pair не разрывается.
`truncatedFields` перечисляет `line` и/или `normalized:<JSON Pointer>`; сокращённая
JSON-строка события может перестать быть JSON, но внешний MCP-ответ всегда валиден.

Проекция и сокращение не уменьшают число событий сами по себе: `completeness`
описывает охват записей, а `EVENT_FIELDS_TRUNCATED` — содержимое полей.
Кеша пока нет: `PROJECTION_APPLIED_ORIGINAL_NOT_CACHED_DETAILS_UNAVAILABLE`
явно предупреждает, что скрытое/сокращённое содержимое нельзя раскрыть по ID.
`entryId` и `getLogEntry` исключены вместе с S07. Детали — уточняющий запрос Loki;
продолжение — [stateless cursor S08](pagination.md). После `line_format` исходный
текст до pipeline может быть утрачен ещё в Loki.

## Бюджет wire response

`maxResponseBytes` подключения применяется к успешным ответам всех трёх data tools.
Измеряется UTF-8 сериализация полного JSON-RPC ответа: `jsonrpc`, фактический `id`,
`result`, `content` с экранированным text payload, `structuredContent`, `isError`,
служебные поля и завершающий LF. Используется тот же mapper, что у stdio writer.
Проверка выполняется в декораторе штатного транспорта SDK перед отправкой;
HTTP body имеет отдельный лимит. Прямые Java-вызовы сервисов не являются wire-ответами
и не применяют этот транспортный бюджет.

При превышении лимита:

1. Текст событий и примеров discovery дополнительно сокращается, с повторным замером.
   Нижний целевой размер — 128 code points плюс маркер; короткие строки не изменяются.
2. Удаляется хвост массива событий с очисткой словаря. Для метрик сокращаются ряды,
   затем samples единственного оставшегося ряда. Массивы уменьшаются вдвое: это
   консервативный размер выдачи, максимальное заполнение бюджета не обещается.
3. У discovery сокращаются примеры, обнаруженные поля, stream labels и форматы.
   Capability, scope, window и счётчики обследования остаются. Крупные метки и metadata
   не подменяются обрезанными значениями; при необходимости исключается их запись.
4. Если обязательные поля не помещаются, возвращается `ToolError` с
   `isError=true`, `RESPONSE_BUDGET_EXCEEDED` и предложением уменьшить детализацию/scope
   либо увеличить бюджет. Исходные данные не включаются в ошибку.

Сокращения по размеру отмечены `RESPONSE_BYTE_BUDGET`. При исключении записей/точек
`completeness=PARTIAL`, `returned*` отражают фактическую выдачу, `read*` не меняются.
Порядок оставшихся событий и реальная кратность повторов сохраняются.
У queryLogs/continueLogs курсор рассчитывается по фактически выданному префиксу
и входит в бюджет. У метрик и discovery продолжения нет.
У discovery `coverage.localTruncation=true` относится также к сокращению выдачи;
`entriesExamined` и `sampleCompleteness` описывают обследованную выборку, не размер
списка примеров. Сокращённые примеры имеют `EXAMPLE_FIELDS_TRUNCATED` в limitations.
Отсутствие поля/метки/примера в сокращённом ответе не доказывает отсутствие в данных.

У `listConnections` нет connection: его бюджет — 65536 байт; при превышении выдаётся
ошибка, частичный каталог не возвращается. Безопасные tool errors имеют общий предел
1024 байта, не превышающий минимальную настройку любого подключения. `initialize`,
`tools/list`, ping и прочие протокольные сообщения не являются data tool responses.
Клиентский `id` должен оставлять место для ответа: если даже ограниченная ошибка с ним
не помещается, транспорт завершается ошибкой, не отправляя превышающий бюджет JSON.
Рекомендуются короткие числовые ID или UUID.

## Проверки

`gradlew.bat build --console=plain` проверяет проекцию, схемы, Unicode, большие
stack traces/метки/metadata, дубликаты, точную границу байтов и минимум 1024.
Stdio smoke запускает jar и проверяет 16 outstanding больших ответов с разными
бюджетами подключений и экранированными строковыми ID, фактические байты stdout,
схемы и равенство text/structuredContent. Docker для этих проверок не нужен.
