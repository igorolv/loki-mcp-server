# Продолжение логов без кеша событий

S07 с кешем событий, entryId и getLogEntry исключён по решению пользователя.
S08 добавляет `continueLogs(connection, cursor)`. Детали получают новым уточнённым
`queryLogs`, а продолжение — через `nextCursor` предыдущего ответа.

```json
{"connection":"local","query":"{job=\"example\"}","start":"now-15m","end":"now","direction":"forward","limit":20,"fields":["line"]}
```

Если ответ содержит `nextCursor`, следующий вызов:

```json
{"connection":"local","cursor":"<nextCursor>"}
```

`limit` задаёт максимум записей в MCP-странице. `upstreamFetchLimit` показывает
фактический HTTP limit: настроенный `maxEntries`. Он больше размера страницы,
если это нужно для пересечения и сведений о продолжении. Каждый вызов делает один
ограниченный HTTP-запрос; автоматически дочитывать все страницы сервер не будет.
Большая выборка остаётся внутри процесса только на время подготовки текущего ответа.

`queryWindow` — исходное фиксированное окно. `window` — окно фактического повторного
запроса. `now` не пересчитывается на следующих страницах. `readEntries` включает
повторно прочитанные записи границы; суммировать его между страницами как число
уникальных совпадений нельзя. `returnedEntries` — число событий данной страницы.
Метрики и discovery пока не имеют продолжения.

## Курсор и граница

Курсор не содержит событий. Он хранит connection, запрос, окно, направление, fields,
размер страницы, срок действия, последний timestamp и число/цепочку SHA-256 уже
выданных записей на этом timestamp. AES-GCM шифрует и аутентифицирует содержимое;
случайный ключ живёт в памяти процесса. Таблицы курсоров или кеша событий нет.
Срок действия всей цепочки — 15 минут с первой страницы, без продления.

Перед проекцией события сортируются по timestamp и детерминированному fingerprint
полного query-output события: строка, result labels и structured metadata.
Идентичные события сохраняют кратность; hash не используется для удаления всех копий.
Следующий запрос перечитывает boundary включительно и сверяет уже выданный префикс.
Только после проверки пропускает ровно указанное число экземпляров.

По [контракту Loki](https://grafana.com/docs/loki/latest/reference/loki-http-api/#query-logs-within-a-range-of-time)
`start` включающий, а `end` исключающий. Для forward используется start=boundary;
для backward — end=min(originalEnd, boundary+1ns), чтобы повторно включить boundary.
Это не сдвиг за непрочитанные события. Наносекунды передаются строками.

Контрольные суммы вычисляются до сокращения текста. Транспорт выбирает курсор
**после** сокращения массива по wire budget: он соответствует последней реально
выданной записи. Внутренний draft живёт лишь до отправки ответа; его служебная metadata
удаляется до сериализации в stdout. Сам nextCursor входит в обе части payload и бюджет.

## Гарантии и остановки

Для неизменной воспроизводимой выборки с проверяемой границей страницы сохраняют
общую хронологию и кратность. Snapshot isolation отсутствует: поздние записи в уже
пройденной части окна могут не попасть в продолжение. Это явно указано через
`REQUERY_NO_SNAPSHOT_LATE_ARRIVALS_MAY_BE_MISSED`. Digest проверяет только overlap,
а не всю историю. Изменение скрытого проекцией содержимого тоже учитывается.

`continuationUnavailableReason`:

| Значение | Значение для клиента |
|---|---|
| `NONE` | Используйте nextCursor |
| `END_OF_RESULTS` | В текущем повторном запросе нет остатка и upstream limit не достигнут |
| `BOUNDARY_SATURATED` | Timestamp заполнил весь HTTP limit; безопасно пройти его нельзя |
| `RESPONSE_BUDGET_NO_PROGRESS` | Даже одна запись с курсором не вошла в выдачу |
| `CURSOR_STATE_TOO_LARGE` | Параметры запроса не помещаются в ограниченный курсор |
| `UPSTREAM_WARNINGS_NO_SAFE_CONTINUATION` | Нет остатка, но upstream не подтвердил полноту |

Сервер не угадывает исходные stream selectors по result labels и не делает fan-out
для обхода насыщения. При изменившемся порядке набора на насыщенной границе возможен
консервативный отказ, даже если сами данные не менялись. Отсутствие nextCursor при
UNKNOWN/PARTIAL не означает, что прочитаны все совпадения. Сужайте scope/интервал
или обоснованно меняйте лимит подключения.

`INVALID_CURSOR` означает повреждённый токен, другое подключение или другой процесс
(включая перезапуск). `CURSOR_EXPIRED` — истёкший срок. `CURSOR_STALE` — не удалось
подтвердить пересечение; запрос не возвращает похожие записи вместо прежних.
Ошибки не отражают token/query или upstream diagnostics. Токен ограничен 24000 символами.
Если обязательный ответ не помещается, остаётся ошибка `RESPONSE_BUDGET_EXCEEDED` S06.

## Проверки

`gradlew.bat build --console=plain`: unit-проверки обеих направлений, потоков и
идентичных дубликатов, перестановки upstream ties, скрытых изменённых полей,
wire truncation, TTL, повреждения/изоляции/перезапуска, фиксированного now и насыщения.
Jar smoke проверяет 16 outstanding continueLogs, schema, фактические байты и отсутствие
внутренней metadata. `gradlew.bat integrationTest --console=plain` проверяет forward/
backward страницы на Loki 2.6.1/3.6.0, включая timestamp, общий для нескольких потоков.
